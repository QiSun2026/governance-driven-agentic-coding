Integration map · GDAC v2.0

Use the controls that already exist

GDAC is not a new branch-protection tool, policy engine, eval runtime, or provenance format. It connects those mechanisms to one delegated outcome, one exact candidate, and one accountable disposition.

Position

The contribution is the binding protocol

The individual controls are familiar. GDAC's proposed unit is the chain that keeps them attached to the same task and object.

frozen outcome + authority→ exact candidate→ declared evals→ evidence→ aggregate gate→ Owner disposition

A team should be able to connect an issue, checked-in Contract and Eval Plan, commit SHA, CI or evaluation output, Gate Record, and maintainer decision without creating a second project-management system.

Engineering

Nearest engineering neighbors

These mechanisms remain the enforcement and execution layers. GDAC should consume their outputs instead of reimplementing them.

Repository enforcement

Merge, ownership, and required checks.

Protected branches and required checks

GitHub can enforce reviews, status checks, signed commits, and merge conditions. GDAC states why those checks are required for this task and binds their result to the claim and candidate in the Gate Record.

CODEOWNERS

CODEOWNERS routes path-level review. GDAC records task-level Owner authority, principal/context separation, and whether the approval is technical evidence or the later accountable disposition.

Policy and permissions

Decide and enforce what an Agent may do.

Open Policy Agent

OPA evaluates machine-readable policy and can run in CI/CD. A GDAC validator can call or be called by it; GDAC supplies the surrounding Contract, candidate/evidence binding, fail-closed state, and human disposition.

Agent runtime permissions

Claude Code and other runtimes can restrict tools, commands, and files. The Outcome Contract makes that authority portable, but the runtime must enforce it. A YAML write scope is not a sandbox.

Evaluation

Run tests, scorers, agents, and logs.

Inspect and Inspect logs

Inspect supplies evaluation execution, limits, scorers, tools, and inspectable logs. GDAC wraps the selected eval runtime with task authority, exact claim/candidate binding, aggregation rules, and the separate Owner disposition.

Artifact identity

Provenance and attestations.

in-toto, SLSA, and artifact attestations

These systems bind artifacts to authenticated build steps, identities, and provenance statements. GDAC evidence can reference them. The starter validator checks file digests but does not itself authenticate producers or provide tamper-resistant provenance.

Repository records

Instructions and decisions that remain useful.

Architecture Decision Records

ADRs preserve architectural context and consequences. The Outcome Contract instead freezes task result, delegated authority, budgets, stops, and evidence before implementation. A project can use both.

AGENTS.md

AGENTS.md gives coding agents repository-wide setup, conventions, and security guidance. GDAC references that environment and adds a task-level Contract plus post-build decision chain.

Overlays

Broader risk frameworks operate at another level

NIST AI RMF, the IIA Three Lines Model, and the EU AI Act address organizational risk, assurance, or legal obligations beyond one coding task.

What a regulated-environment overlay may do

Map

Link task records and evidence to an organization's control or documentation requirement.

Flag

Preserve unresolved legal role, classification, competence, independence, and evidence questions.

Not decide

It cannot establish legal role, conformity, compliance, internal-audit independence, or third-party assurance.

Design test

Integration is the credibility test

A GDAC term earns its place only when it changes authority, object identity, evidence sufficiency, or a permitted state transition. Otherwise, use the existing tool's vocabulary.

Current evidence

The repository demonstrates the structure and deterministic rules on included cases. Whether teams adopt the protocol and whether it improves production outcomes remain questions for external use and comparison, not claims embedded in the architecture.
