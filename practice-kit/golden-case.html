Record chain

Every object answers a different question

The example is intentionally small. The point is not the cleanup function; it is the trace from delegated authority to a decision-ready record.

  1. Outcome ContractWhat must be true, which risks matter, who may write, and where the task must stop.
  2. Eval PlanWhich claims and risks are tested, by which grader, with which evidence and budgets.
  3. Candidate BindingThe exact candidate.py digest, source revision, and attempt under review.
  4. EvidenceTest, rule, log, regression, adversarial, and diff records, each with a stable reference and digest.
  5. Eval resultsOne state per planned eval, bound to the same candidate and declared trial count.
  6. Harness GateDeterministically ready because every blocking eval passes and no material finding remains open.
  7. Owner dispositionpending. Technical readiness does not accept or publish the work.
Important distinction

A snapshot records a state. A Candidate Binding identifies what is being evaluated. Evidence records observations about it. The Harness Gate aggregates declared results. The Owner disposition is a separate exercise of authority.

Failed attempt

The example keeps the attempt that did not prove the claim

The first attempt relied on a before-and-after filesystem snapshot. That was rejected because a temporary write could occur and disappear before the final snapshot.

From supporting evidence to direct evidence

build-0 · rejected

The snapshot showed the same final files, but could not establish that no temporary or metadata write was attempted.

build-1 · completed

The test instruments the candidate's application-level Path.unlink operation and keeps the snapshot as corroboration.

Declared limit

The fixture inventories and instruments the write API used by the bundled candidate inside its process and fixture boundary. It does not cover unlisted libraries, child processes, or operating-system-wide writes.

Gate derivation

Five blocking evals, one aggregate state

Each pass must include every evidence type frozen by its Eval Plan entry. The validator also checks file digests, candidate identity, attempt references, trial counts, contradictions, findings, and budgets.
